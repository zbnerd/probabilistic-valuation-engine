## 이 책을 쓰면서

이 책은 과거의 장애 기록이 아니다. **미래의 장애에 대한 준비**다.

각 장은 하나의 패턴을 담고 있다:

```
1장: 외부 의존성은 항상 실패한다 → 서킷 브레이커
2장: 장애는 격리되어야 한다 → Resilience4j
3장: 리소스는 유한하다 → 커넥션 풀 관리
4장: 동시성은 폭풍을 만든다 → SingleFlight
5장: 새 기술은 새 문제를 만든다 → Virtual Thread 주의
6장: 락은 양날의 검이다 → Advisory Lock 원칙
7장: 마지막 방어선도 죽을 수 있다 → 알림 격리
8장: 상태와 카운트는 하나여야 한다 → 원자적 연산
9장: 복잡성은 장애의 온상이다 → 단순화
10장: 장애는 실험으로 이해한다 → 장애대응 테스트
11장: 일관성은 규율에서 나온다 → Zero Try-Catch
12장: 측정만이 진실이다 → 관측성
```

## 독자에게

이 책을 읽는 당신이 겪는 장애는 우리와 다를 것이다. 하지만 원칙은 같다:

1. **장애를 두려워하지 마라.** 장애는 발생한다. 중요한 것은 대응이다.
2. **측정하라.** 측정하지 않으면 개선할 수 없다.
3. **단순하게 만들어라.** 복잡성은 장애의 친구다.
4. **격리하라.** 한 컴포넌트의 장애가 전체를 죽이게 하지 마라.
5. **기록하라.** 오늘의 장애는 내일의 가드레일이다.

## 마지막으로

probabilistic-valuation-engine은 여전히 진화 중이다. 7,347 RPS는 다음 목표를 위한 출발점이다. 장애대응 테스트는 계속 추가될 것이다. 가드레일은 계속 늘어날 것이다. 그리고 새로운 장애도 발생할 것이다.

하지만 이번에는 다르다.

장애가 발생하면, 서킷 브레이커가 트립할 것이다. 알림이 울릴 것이다. 운영자가 즉시 알 것이다. 시스템은 부분적으로 동작할 것이다. 그리고 복구될 것이다.

**"장애는 언제 들이닥칠지 모른다. 하지만 장애 앞에서 어떻게 반응할지는 우리가 결정한다."**

이것이 3개월의 여정이 남긴 가장 중요한 교훈이다.
