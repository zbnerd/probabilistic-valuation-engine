# ADR 통합 및 검증 작업 설계서

## 개요

산재된 ADR(Architecture Decision Record) 문서를 단일 위치로 통합하고, 각 ADR의 결정사항이 실제 코드에 반영되었는지 검증하는 작업.

## 배경

### 현재 상황
- ADR 문서가 3개 디렉토리에 분산되어 있음
- 중복 번호 존재 (ADR-035, 036 등)
- .backup 파일 다수 존재
- 문서와 실제 구현 간 일치 여부 미확인

### 파일 분포
| 위치 | 파일 수 | 비고 |
|------|--------|------|
| `docs/adr/` | 2개 | ADR-035, 036 (최신) |
| `docs/01_ADR/` | 47개 | backup 파일 포함 |
| `docs/01_ADR/` | 44개 | V5 CQRS 등 |

## 작업 범위

### Phase 1: ADR 통합

**목표:** 모든 ADR을 `docs/01_ADR/`로 통합

**작업 내용:**
1. `docs/adr/` → `docs/01_ADR/` 이동 (ADR-035, 036)
2. `docs/01_ADR/` → `docs/01_ADR/` 이동 (47개)
3. 중복 파일 처리: 최신 수정일자 파일로 덮어쓰기
4. `.backup` 파일 제거
5. 비표준 파일(README, ENHANCEMENT_*)은 별도 보관 또는 정리

**예상 결과:** `docs/01_ADR/`에 70+ ADR 파일 통합

### Phase 2: ADR 검증

**목표:** 각 ADR의 결정사항이 실제 코드에 반영되었는지 검증

**검증 항목:**
| 섹션 | 검증 내용 |
|------|----------|
| Context | 문제 상황이 현재도 유효한지 |
| Decision | 결정된 아키텍처/패턴이 코드에 존재하는지 |
| Implementation | 명시된 파일/클래스가 실제 구현되었는지 |
| Consequences | 예상된 효과/부작용이 실제 발생했는지 |

**에이전트 팀 구성:**
```
Team Lead: 전체 조율
├── Explorer x 3: ADR별 코드 탐색 (각 20-25개 담당)
├── Architect: 아키텍처 준수 검증
├── Code Reviewer: 구현 품질 검증
└── Writer: 검증 결과 리포트 작성
```

### Phase 3: 불일치 수정

**케이스바이케이스 판단 기준:**

| 상황 | 액션 |
|------|------|
| ADR이 더 합리적 + 구현 누락 | 코드 수정 (ADR 준수) |
| 구현이 더 합리적 + ADR 구식 | ADR 수정 (현실 반영) |
| 둘 다 문제 | ADR 재작성 + 코드 리팩토링 |
| 단순 문서 오류 | ADR 수정만 |

## 산출물

1. **통합된 ADR 디렉토리**: `docs/01_ADR/`
